# 南农智农院 - AI组织部 · AI Organization Department

面向南京农业大学智慧农业学院（人工智能学院）团委组织部的一体化写作前端/后端工程。它把多个既有 skill（`plan_skill` 策划案、`QQ_push_skill_v2` QQ 空间推送、`push_pic_skill` 配图提示词、`wechat_push_skill` 微信公众号推送、`time_skill` 学时申请与认定）的提示词工程固化为后端系统提示词，通过大模型 API 完成文案撰写，并提供网页编辑器供二次修改、选中文字定向修改与文本导出。


## 功能

- **策划案撰写**：严格套用学院组织部固定模板结构（封面→背景→目的→…→预算→附件，不含落款），结尾附"待确认清单"。
- **QQ 空间推送撰写**：按部门/推送类型风格撰写。
- **微信推送撰写**：贴合官方公众号（CollegeSA&AI NAU）调性。
- **学时申请 / 认定**：按「学时申请表 / 学时认定表」引导式生成，可加载/导入一份策划作为事实依据（解析式填写）。
- **配图提示词**：为已完成推送一键生成主图 + 辅助配图提示词；生成前可在「配图参数」弹窗里选择比例 / 数量 / 风格 / 用途平台 / 主图文字 / 色彩倾向。
- 右侧 Markdown 编辑器：可在线编辑、切换预览。
- **选中文字定向修改**：选中一段文字会弹出修改条，针对该段提意见即可让模型只改写该片段；改写过程中视口保持不变，不会自动跳到文本末尾。
- **待确认清单回填**：策划案生成后，左侧出现"📋 填写待确认清单并出定稿"，界面直接从策划文本里自动识别待确认项，逐项填写后模型回填占位符并输出定稿。
- **导入 / 从存档加载策划 → 写推送 / 学时**：在 QQ / 微信 / 学时模式下，可点「📄 导入策划案」选 `.docx`，或点「📂 从存档加载策划」从我的存档选一份已保存的策划，生成的推送/学时表会以该策划为事实依据。（策划案模式不显示这两个按钮。）
- **我的存档**：任一写作成果可命名保存到浏览器本地（localStorage）；保存时会把左侧的活动/需求配置一并保存，载入时一并还原，随时改名、导出或删除。
- **多主题界面**：顶栏可切换 经典红 / 浅蓝 / 浅绿 / 浅黄 / 深色 主题（本地记忆）。
- **输出视图**：编辑 / 预览 / **纯文本** 三种视图。纯文本去除所有 Markdown 符号，可直接复制进 QQ / 公众号编辑器。
- **导出**：`.md`、纯文本 `.txt`、**Word `.docx`**（公文排版，见下）。
  - Word 导出按 `模板.docx` 排版：A4 + 同页边距，正文仿宋四号（西文 Times New Roman）、首行缩进 2 字符、固定行距；一级标题黑体四号、二级楷体四号、三级仿宋四号；策划案自动套用其封面并分页；预算以真实表格导出；"待确认清单"不写入 Word。
- 一键生成 / 整体润色 / 复制 / 复制纯文本。

## 技术栈

- 后端：Node.js + Express（原生 `fetch` 流式转发，无多余框架）。
- 前端：原生 HTML / CSS / JS 单页（多主题 CSS 变量，无构建步骤）。
- 大模型：支持 OpenAI 兼容协议的两个提供商。
  - **智谱 GLM-4.7-Flash（免费）** —— 默认，模型名 `glm-4.7-flash`，仅需填入智谱开放平台 API Key。
  - **DeepSeek deepseek-v4-flash** —— 模型名 `deepseek-v4-flash`，需填入 DeepSeek 开放平台 API Key。

## 目录结构

```
ai-writer-app/
├─ package.json
├─ server/
│  ├─ index.js      # Express 服务 + 静态托管 + API（含公文版 .docx 导出、预算表格）
│  ├─ config.js     # 模型配置读写（存于 data/config.json）
│  ├─ skills.js     # 按功能加载各 skill 的 md 文件拼装系统提示词
│  └─ llm.js        # 统一流式调用 GLM / DeepSeek
├─ public/          # 前端（index.html / style.css / app.js）
└─ data/            # 运行期生成 config.json（apiKey 本地保存）
```

> 技能文件直接引用工程外层的 skill 仓库（`../plan_skill`、`../QQ_push_skill_v2`、`../push_pic_skill`、`../wechat_push_skill`、`../time_skill` 及根目录 `模板.docx`），不在此目录内复制，保证提示词与给定 skill 始终同步。

## 启动

前置：Node.js ≥ 18。

```bash
cd ai-writer-app
npm install
npm start
```

打开浏览器访问：http://127.0.0.1:5503

## 使用步骤

1. 首次使用点右上角 **⚙ 模型设置**，选择提供商（智谱 GLM-4.7-Flash / DeepSeek deepseek-v4-flash），填入对应 API Key 并保存。Key 仅保存在本机 `data/config.json`。可用"测试连接"按钮验证 Key 与网络是否正常；顶栏旁也可切换界面主题。
2. 左侧顶部切换要写的类型：**策划案 / QQ 空间推送 / 微信推送 / 学时**。
   - 学时模式先在"办理类型"选择 **学时申请**（生成申请表）或 **学时认定**（生成认定表），再填对应字段。
3. 填写活动 / 需求信息（可按需只填部分，缺失项由模型用默认值补全并标注），补充说明可选。
4. 点 **✦ 生成全文** → 流式输出到右侧编辑区。
   - QQ / 微信生成后，点 **🖼 为当前文案生成配图提示词**，可先选好参数再生成。
   - 想对整篇润色：点 **整体润色 / 修改**。
5. 在右侧选中一段文字 → 底部弹出"✎ 已选中"修改条 → 在输入框填针对该段的修改意见 → **应用**（仅改写选中片段，视口不跳）。
6. **策划案定稿**：草稿含"待确认清单"时左侧会出现 **📋 填写待确认清单并出定稿**，逐项填写后生成回填占位符的定稿。
7. **据策划生成**：QQ / 微信 / 学时模式下，点 **📄 导入策划案**（`.docx`）或 **📂 从存档加载策划**，提取/载入策划全文后点生成，输出会以该策划为事实依据。
8. **保存成果**：点 **💾 保存当前**，输入标题保存到"我的存档"（连同左侧配置）；存档可随时载入 / 改名 / 导出 / 删除，数据存于浏览器 localStorage。
9. **输出**：右侧顶部可切 **编辑 / 预览 / 纯文本**；导出支持 `.md`、`.txt`（纯文本）、**Word `.docx`**（公文排版、预算表格、策划封面）。

## API 一览

- `GET  /api/config` 读取当前模型配置（不含 key）。
- `POST /api/config` 保存提供商与 API Key。
- `GET  /api/modes` 返回各功能系统提示词规模（自检用）。
- `POST /api/test` 轻量连接测试。Body：`{ provider }`。
- `POST /api/chat` 流式生成。Body：`{ mode, messages, provider? , temperature? }`，`mode ∈ {plan, qq, pic, wechat, time}`。返回 `text/plain` 增量文本流。
- `POST /api/import-docx` 导入 Word。Body 为 `.docx` 原始字节，返回 `{ text, chars }`。
- `POST /api/export-docx` 导出 Word（公文排版、预算表格、策划封面）。Body：`{ text }`，返回 `.docx` 文件。

## 说明

- 各功能的系统提示词分别由下列 skill 文件拼装：
  - 策划案 → `plan_skill/SKILL.md` + `references/knowledge-base.md`
  - QQ 推送 → `QQ_push_skill_v2/SKILL.md` + 其全部 `references/*.md`
  - 配图提示词 → `push_pic_skill/SKILL.md` + 其全部 `references/*.md`
  - 微信推送 → `wechat_push_skill/SKILL.md`
  - 学时申请 / 认定 → `time_skill/time.md`
- **输出约束**：正文如需分点一律用有序数字列表（QQ 推送不使用任何列表、仅换行分段）；除策划案的"经费预算"外不得使用表格；待确认清单用有序列表。这些约束在 `server/skills.js` 与各 skill 中说明。
- **隐私**：为保护个人隐私，功能型 skill（如人员表、公众号把关人、学时示例）中的真实人名 / 学号 / 联系方式已做确定性占位处理；但 `wechat_push_skill/references/analysis/r00-r19.md`（未注入运行时、体积很大的语料分析文件）仍含大量真实人名与账号信息，对外发布前请务必审阅或另行脱敏。
- 大语料参考库（如 `messages.json`、`extracted_texts.json`）体积过大，未整体注入，仅在技能文件指引下由模型按规范创作。如确需注入参考语料，可在此工程中按需对指定数据抽样后附加到 `server/skills.js` 的对应清单。
